# PROJECT RULES

## 1. Научный стандарт
- Разделять факт, гипотезу, предположение и результат теста.
- Для каждого утверждения хранить источник или расчёт.
- Не путать корреляцию, красивый паттерн и предсказательную силу.
- Любую стратегию проверять out-of-sample, а не только на данных, по которым она придумана.
- Учитывать multiple testing / data snooping: при тысячах гипотез случайные «успехи» неизбежны.

## 2. Что считается успехом
Стратегия интересна только если после всех реальных расходов она показывает положительное ожидаемое значение или иной доказуемый арбитраж при приемлемом риске.

Обязательно учитывать:
- цену билета/ставки;
- комиссии;
- налоги;
- разделение джекпота между победителями;
- лимиты покупки;
- ликвидность/доступность;
- вероятность отмены/изменения правил;
- валютный риск, если применимо;
- стоимость получения данных и исполнения стратегии.

## 3. Никакой псевдонауки
Можно исследовать любую серьёзную математику, физику, теорию информации, оптимизацию, статистику, ML и т.д., но терминология сама по себе ничего не доказывает. «Квантовый» подход принимается только если есть физический механизм или проверяемая математическая модель, дающая предсказание лучше базовой модели.

## 4. Гарантии
Не называть стратегию «гарантированно прибыльной» без строгого доказательства всех исходов и исполнения. Если гарантия условная, условия должны быть перечислены явно.

## 5. Эксперименты
Для каждой гипотезы вести:
- ID;
- формулировку;
- математическое обоснование;
- источник идеи;
- данные;
- метод теста;
- baseline;
- train/test или historical/forward split;
- результат;
- доверительный интервал;
- статус: rejected / inconclusive / promising / validated.

## 6. Вычисления
Не перебирать триллионы комбинаций вслепую, если пространство можно сократить аналитически, симметриями, динамическим программированием, integer programming, sampling или Monte Carlo.

## 7. Исторические данные
Хранить сырые данные отдельно от очищенных. Сырые данные не изменять вручную. Все преобразования должны быть воспроизводимыми кодом.

## 8. Реальные деньги
Исследовательский результат и решение поставить реальные деньги — разные этапы. Результаты симуляции не считать обещанием прибыли.

## 9. GO-mode и сохранение прогресса
- Сообщение пользователя `го` означает: без уточняющих вопросов продолжить следующий наиболее ценный исследовательский пакет из `STATUS.md` / очереди.
- В чате писать минимум: промежуточно только критическое открытие, в конце только `SUCCESS` или `ЕЩЁ НЕ УСПЕХ` + одна короткая причина.
- После каждого meaningful пакета обязательно сохранить выводы, данные/код и обновить checkpoint в GitHub.
- `STATUS.md` — текущая точка продолжения; `research/CHECKED_PROJECTS_AND_TESTS.md` — полный журнал проверенных игр, проектов, гипотез и вариантов тестов.
- Не повторять уже закрытый тест без новой информации/метода.

## 10. Терминальные состояния проекта
### SUCCESS
Можно завершить поиск как успех только если найдена стратегия с **строго доказанной гарантией положительной чистой прибыли** при явно перечисленных выполнимых условиях и после цены, налогов, комиссий, sharing, лимитов, исполнения и прочих расходов. Positive EV без гарантии — сильный результат, но не терминальный SUCCESS.

### EXHAUSTED
Если SUCCESS не найден, путь считается завершённым только после систематической проверки всех разумно сформулированных классов возможностей, занесённых в реестр, включая появившиеся в ходе исследования новые ветви. `research/CHECKED_PROJECTS_AND_TESTS.md` должен позволять позже увидеть, что именно проверялось, каким методом и почему ветвь закрыта/остаётся открытой.
